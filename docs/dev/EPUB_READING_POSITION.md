# Stable EPUB reading positions — 0.0.109

Page boundaries change with viewport size, toolbar height, reading mode and writing direction. The requested source character is now retained separately from the first visible character on its containing page. For example, reopening at character 23 can display a page beginning at character 20; workspace and progress saves retain 23. Repeated mode changes therefore do not walk backward through page starts.

The retained anchor applies only while its character is visible in the current chapter, or while that chapter has no visible host layout. Pointer/touch input, wheel scrolling, reading-navigation keys and explicit page turns release it. Search or annotation navigation releases it when it actually scrolls to a result. An anchor that becomes offscreen also expires, so external scrolling is not masked. Composition and keyCode 229 events do not release it. Old detached viewports cannot release a new reader's anchor. No new persisted schema is needed: positions remain chapter plus UTF-16 source offset. The internal leading-offset measurement remains separate and unchanged.

A regression failed before the fix: the requested offset 23 became saved page start 20. It now checks four mode switches, workspace/progress retention, pointer/keyboard release, composition guards, offscreen expiry and detached viewport ownership. Earlier pagination tests were updated only where they intentionally encoded the old saved-page-start behavior; page geometry still reports its actual leading character.

The real-browser corpus now includes a responsive EPUB whose HTML root changes from vertical-rl to horizontal-tb below 750 CSS pixels, inherited by its body. Eight writing/mode combinations pass at both 900- and 397-pixel initial reader widths, including native reading-mode controls, repeated mode changes, proportional resizing, responsive direction changes, pointer selection/published anchoring, chapter windows and reopening. In the original wide vertical scroll case, before the fix the saved offset moved from 914 to 762 and later 405 as controls/modes changed. With the fix it remains 914 while actual page-leading offsets can still be 762 or 861. The requested passage stays visible.

This is actual browser geometry with the existing test-only Obsidian boundary, not a new Android or desktop Obsidian run. Installed Android remains 0.0.107. All 372 tests and release/original-ID rehearsal checks pass. No vault data, annotation format or Bend theorem changed. Actual device repeated-reflow behavior, wider typography/corpora and the remaining native replacement gates stay open.

## Saves between reflow and observer delivery — 0.0.115

Workspace/progress saves can run after a viewport dimension changes but before ResizeObserver delivers the restoration callback. Previously readingOffset checked the requested character against the displaced geometry, expired its retained anchor, and could replace the pre-resize source position. A deterministic regression shrinks a paginated viewport without delivering its observer: requested offset 23 was incorrectly saved as 16.

readingOffset now returns the last layoutPosition while the viewport dimensions differ from the recorded layout dimensions. The observer then restores that passage through the existing lifecycle. The check precedes chapter/character measurement, so an intermediate continuous layout cannot select another chapter either. Initial/restoring states retain their existing handling. Once dimensions are reconciled, actual manual navigation and offscreen-anchor checks still apply.

The regression covers workspace serialization, queued progress and direct progress save before observer delivery, observer restoration, and subsequent manual navigation. It failed on the old code; all 378 tests now pass, along with release/original-ID rehearsal builds. The isolated browser corpus passes all eight writing/mode cases at narrow width, and the expanded wide corpus synchronously forces reflow then calls getState, queueProgress and saveProgress before yielding to an animation frame. All eight wide cases retain the requested offset, including the responsive writing-direction breakpoint, and retain the later restored passage. Existing actual pointer selection/frozen published anchoring, mode controls, resize, reopen and chapter-window checks still pass.

Evidence: `~/Documents/obsidian-annotator-native-test-validation/2026-11-02-pre-observer-save/narrow/` and `wide-save-race/`; regression failure log `/tmp/annotator-save-resize-before.log`. Reproduce the browser check with `test-support/browser-vertical-epub-check.mjs`; its resized report includes beforeObserverSave with requested, serialized and saved positions.

This fixes the demonstrated save-before-observer race. It does not establish that this was the cause of the earlier Android 200→178 observation. Installed Android remains 0.0.114; no actual-host check of 0.0.115, personal-vault change, schema migration or Bend proof change is claimed.
