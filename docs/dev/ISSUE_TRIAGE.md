# Open issues against the native reader

Triage of every open issue of elias-sundqvist/obsidian-annotator as of 2026-11-11, judged against the native reader in `experiments/native-pdf` on branch `experiment/native-design`. Each issue was read with its comments (bodies over about 500 characters and threads over four comments in abridged form; issues 135, 218, 314 and 384 in full); each status rests on the code, test names and evidence notes of that directory. Nothing was built or run for this document, and nothing was posted to GitHub.

There are **271** open issues, not about 60. The plan task `issue-triage` in `.github/unblock.json` should be corrected.

How to read the statuses:

- ADDRESSED and FIXED-BY-DESIGN describe the native reader, which is not released. For users of the published 0.2.11 nothing has changed yet.
- Most tests cited run against a host stub in Node. Where live checks are still open in `PARITY.md` (Dataview targets, default opening, Windows, minimum host version) the row says so.
- iOS is untested throughout, so iOS-only reports are NEEDS-VERIFICATION whatever the code says.
- Issues about rendering or text selection inside the PDF page now depend on Obsidian's own PDF view. They are NEEDS-VERIFICATION unless the fault was in a part that no longer exists (the iframe, the bundled viewer's toolbar, its worker and fetch routes).

### Security and data-loss reports

- **Issue 384, remote code execution.** A crafted EPUB runs script with Node access in the published plugin (`src/defineEpubAnnotation.tsx` still sets `allowScriptedContent: true`). The native EPUB view never runs book scripts. A regression test with the reporter's proof of concept and a fix or advisory for 0.2.11 are still open (plan task `security-384`).
- **Issue 85.** Annotations moved into a stray "Untitled" note and highlights were lost from the original note. The reporter traced it to an old Obsidian installer.
- **Issues 194, 301, 306 (umbrella), 265, 270, 379, 98.** Annotations stop showing in the reader while the Markdown still holds them. Causes found by reporters: one malformed block hides all the others (194), a linter rewrote the blocks (301, 306), host-specific EPUB addresses (155, 189). In 194 the frontmatter itself went missing.
- **Issue 152 (comments).** Editing a quote in Markdown made every annotation of the note stop displaying.
- **Issue 146.** A comment not explicitly posted is lost when the document closes.
- **Issue 47.** An annotation whose comment has two or more line breaks disappears on reopening (reported fixed in 2021, never closed).
- **Issue 332.** The published plugin requests a script from the hypothes.is CDN at run time, although it is described as offline.
- **Issue 339.** Asks to put a user name and password in the target URL; the native reader refuses such URLs so that credentials never land in a note.
- **Issue 403.** Spam with an outbound link; close and report.

## Verification tests to add

Each item gives the input, the expected behaviour and the host. "Node" means a test beside the existing `*.test.mjs` files; the others are live checks to record in an evidence note.

1. **iOS and iPadOS pass** (issues 289, 166, 177, 225, 322, 89). Host: iPhone and iPad, current Obsidian. Input: the 14-page test PDF and the test EPUB, synced from a Mac with a file name containing spaces. Expected: the plugin loads; a multi-line selection by finger and by Pencil draws a normal selection; the Highlight and Annotate actions are not covered by the system menu; the highlight is saved and shown after a restart; annotations made on the Mac show; tapping a link to an annotation opens the PDF at the passage.
