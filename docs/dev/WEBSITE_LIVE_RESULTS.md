# Real website compatibility check

Checked 2026-10-31 in Obsidian 1.14.5, isolated test vault, on
`experiment/obsidian-native-pdf`.

Source: https://openai.com/index/chatgpt/ (Introducing ChatGPT).
This is a long, scripted article with sticky navigation, sample tabs, code,
inline links, images, footnotes and a cookie banner.

Three records were created manually through the original Annotator plugin's
bundled Hypothesis UI, rather than generated by the native implementation:

1. A wrapped prose sentence, with a Markdown comment and a tag.
2. A complete sentence crossing an inline hyperlink.
3. Five lines of code, including a tab-indented line and line breaks.

Each saved record has the original HTTPS URI and standard Range, TextPosition
and TextQuote selectors. Opening the annotation note's target with the native
command associates that same note with Obsidian's core Web viewer. All three
highlights restore in the live page and after a full application restart.
Visual checks confirm passage boundaries, multiline code geometry, source
formatting, native Markdown comment preview and tag retention. Clicking a live
highlight opens its corresponding native annotation. No edit or migration is
required: `cmp` confirms the complete note remains byte-identical to the copy
saved after creation through the legacy UI.

This test exposed two native defects, now fixed:

- Viewport overlays drew through unrelated sticky navigation. Rectangles outside
  the viewport or covered at their midpoint by an element outside the resolved
  passage are now skipped. This is an occlusion check, not a general pixel-level
  clipping algorithm for all possible website layouts.
- Asynchronous paint responses could overwrite the last completed status poll,
  making the sidebar say “waiting” while the highlight was visible. Completed
  status results are now retained separately from capture/paint responses.

The follow-up scrolling fix replaces viewport rectangles entirely with the
browser's CSS Custom Highlight API. Resolved DOM ranges are painted in their
text layer, so scrolling, clipping and reflow do not require scroll listeners,
rectangle measurement or animation-frame repositioning. The previous midpoint
occlusion workaround is superseded. Hit testing runs only when a user clicks;
selecting text and clicking unrelated controls are preserved. The native sidebar
continues to provide keyboard-accessible annotation controls. An unsupported
Web viewer reports that limitation rather than using a lagging overlay fallback.

The native build/typecheck and 52 reader tests pass, including focused tests for
scrolling without JS repaint, owned highlight/style cleanup, selection-preserving
click handling and status response ordering. The updated plugin was loaded in
Obsidian and checked on the same OpenAI article: native text highlights paint,
remain aligned after scrolling, and open the matching comment when clicked.
The complete annotation note remains byte-identical. A screenshot is retained
alongside the previous website evidence. Static screenshots do not measure
frame-by-frame scroll latency; the regression test verifies that scrolling no
longer schedules JS paint work or measures rectangles.
This is evidence for this page, not a claim
that every scripted website or hidden sample tab has been verified.

Test records, snapshots of the annotation note and screenshots are retained
outside the repository in the isolated vault and its validation directory.
Nothing was uploaded to the public Hypothesis service or added to the personal
vault.
